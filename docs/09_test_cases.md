# 09 Test Cases

> **템플릿.** 테스트 케이스(TC)와 요구사항 연결. 결과는 **실제로 실행한 뒤에만, 증거와 함께** 적는다. 증거가 없는 PASS는 `NOT RUN`으로 취급한다 (`docs/traceability-convention.md` §4).

## 케이스 목록

| ID | 종류 | 대상 (AC / ERR / PERM) | 절차 | 기대 결과 | 테스트 코드 위치 | 결과 |
|---|---|---|---|---|---|---|
| TC-<###> | <정상/예외/경계/권한/회귀> | <AC-###> | <...> | <...> | <경로 또는 `MANUAL`> | NOT RUN |

- 자동화 테스트는 테스트 이름이나 주석에 TC ID를 넣는다 (예: `[TC-104]`). 수동 테스트는 "테스트 코드 위치"에 `MANUAL`을 적는다.

## 실행 증거 (결과가 PASS 또는 FAIL인 TC마다 한 줄)

| TC | 결과 | 실행 일시 | 실행한 명령/절차 | 실행 시점 커밋 | 증거 경로 | 실행자 |
|---|---|---|---|---|---|---|
| TC-<###> | <PASS/FAIL> | <YYYY-MM-DD HH:MM> | <명령 또는 수동 절차> | <커밋 해시> | <`specs/<change-id>/evidence/...` 등> | <누가 실행했는가> |

- 증거 파일(로그, 출력, 스크린샷 등)은 변경 단위의 `evidence/` 폴더에 둔다.
- 실행 시점 이후 관련 코드가 바뀌면 이 줄은 오래된 증거이며 재실행이 필요하다.
- 독립 리뷰어는 증거의 명령을 재실행해 결과가 일치하는지 확인할 수 있다.

## 최소 커버 범위 (`MASTER_PROMPT.md` §5.8)

- 정상: 입력, 저장, 조회, 수정, 삭제/취소 정책, 상태 전이
- 잘못된 경우: 필수값 누락, 잘못된 형식, 권한 없음, 없는 데이터, 중복 요청, 서버 오류, 세션 만료
- 경계값: 0, 최소, 최대, 빈 목록, 매우 긴 문자열, 큰 금액, 많은 데이터
- 회귀: 로그인/로그아웃, 주요 화면, 핵심 API, 저장/조회/수정, 권한, 주요 업무 흐름
